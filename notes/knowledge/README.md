# Knowledge · 知识点库

这里放的是**通用语言 / 系统知识**，跟项目进度无关：

- 目的是「面试能讲清楚」，不是「项目做了什么」。
- 素材可以来自外部文章、书、官方文档，但**必须经过核对**——写进来的每一段代码都要能编译、每一个结论都要能在真实代码或标准里找到依据。
- 每篇文档末尾必须有**映射表**（这些知识点在本仓库对应哪些文件行号）和**自检题**，否则不足以验收。

与 `notes/` 根目录的区别：

| | `notes/*.md` | `notes/knowledge/*.md` |
|---|---|---|
| 内容 | 本项目某个功能的实现记录与决策 | 通用知识拆解 |
| 更新触发 | 功能落地 / 设计变更 | 学习推进 |
| 会过时吗 | 会随代码变化，需持续校准 | 基本不过时 |

## 写作约定

1. **结论先行**，开头放一页速查，正文再展开。
2. 引用外部资料时要**标注出处并列出纠错清单**，不能整段照抄。外部文章的示例代码常常跑不起来，照抄等于把坑搬进来。
3. 代码片段里的注释**只用单行注释**，不写多行注释块。
4. 画图（架构 / 时序 / 调用链 / 状态流转）统一用 ASCII，不放图片。
5. 涉及本仓库时**必须带文件路径和行号**，行号变了要回来改。
